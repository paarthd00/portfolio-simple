What does it mean, and why should you care?

It is strongly associated with modernist architect Ludwig Mies van der Rohe, who popularized the phrase in the 20th century.

This idea applies especially well to software. Fewer abstractions, dependencies, features, and moving parts make systems easier to understand, debug, and maintain. In UI/UX, simple interfaces with a clear hierarchy perform better because users can reason about them quickly. In computer system design and software architecture, restraint often leads to cleaner boundaries, fewer failure modes, and better long-term design.

History of doing more with less in computer science

I guess it has to start with UNIX.

What software clearly inherits this, and what we should point out

I think UNIX is the best example of this. Its development began at Bell Labs in 1969. It is a collection of small utilities that do one thing and do it well. The philosophy is that complex tasks can be performed by combining these utilities together.

Even the utilities less and more are examples of this. They are both used to view text files, but less is more powerful and flexible than more.

LESS

  • Can scroll by single lines
  • Can scroll backwards
  • Does not need to read the entire file before starting
  • Commands are based on both more and vi

From the man page: “Less is a program similar to more (1), but which allows backward movement in the file as well as forward movement. Also, less does not have to read the entire input file before starting, so with large input files it starts up faster than text editors like vi (1).”
